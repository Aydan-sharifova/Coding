# Coding Platform 1.0.0 release notes

Release date: 2026-07-28

Version 1.0.0 establishes the production deployment baseline for Coding Platform: reproducible images, controlled schema migration, persistent data services, health checks, CI/CD, secure configuration, development seed data, and operational documentation.

## Highlights

- Complete collaborative workspace: projects, editor, file history, Kanban, chat, notifications, analytics, administration, realtime presence, and optional AI
- Non-root .NET and Nginx containers built with multi-stage Dockerfiles
- Internal PostgreSQL/Redis/API network with only the edge port published
- Explicit one-shot EF migration job; normal production startup is migration-free
- CI for backend and frontend plus optional versioned GHCR publishing
- Structured production configuration and security review

## Upgrade and deployment

1. Rotate any credentials that have ever appeared in source, chat, or logs.
2. Configure all required `.env.example` values through the deployment secret store.
3. Back up PostgreSQL.
4. Run `docker compose --profile operations run --rm migrate`.
5. Run `docker compose up -d --build` and wait for healthy services.
6. Perform login, project, autosave, chat, collaboration, and AI smoke tests.

## Known limitations

- TLS certificate management is external; production requires a load balancer/ingress in front of Nginx.
- Avatar files use a local named volume. Multi-host deployments need shared object storage and malware/content-signature scanning.
- Presence tracking is process-local while event distribution uses Redis; exact presence behavior during instance failure is eventually consistent.
- The deterministic AI fallback remains available without a provider key; operators should decide whether to disable it for their policy.
- Interactive Swagger is Development-only; a separately published static OpenAPI artifact is not yet generated by CI.
- TypeScript 7 is ahead of the supported parser range for TypeScript ESLint, so the `lint` gate currently performs strict compiler validation rather than stylistic ESLint rules.
- Existing domain models produce nullable-reference compiler warnings that should be reduced in a maintenance release.
- Docker integration tests require a runner with Docker/Testcontainers support.
- Image vulnerability scanning, SBOM signing, SAST, DAST, and deployment promotion are not yet automated.
- A Git tag was not created automatically by this preparation; release owners should create signed tag `v1.0.0` after review and green CI.
